# GitHub pull request workflow

Use this skill when preparing, reviewing, or updating a GitHub pull request.

## Before changing code

1. Check git status and current branch.
2. Identify the base branch.
3. Inspect existing changes to avoid overwriting user work.
4. Pull or fetch the latest base branch when appropriate.

## Before opening a PR

1. Ensure the branch name is descriptive.
2. Run relevant tests and linters.
3. Review the diff yourself.
4. Commit with a concise message.
5. Push the branch.
6. Create the PR with a clear summary and verification section.

## PR description template

```markdown
## Summary
- 

## Verification
- [ ] command/result

## Notes
- 
```

## Safety

Never force-push, delete branches, or rewrite history unless the user explicitly asks.

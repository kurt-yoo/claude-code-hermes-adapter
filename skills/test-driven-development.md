# Test-driven development

Use this skill when implementing a feature or bug fix where tests are practical.

## Process

1. Inspect existing tests and conventions.
2. Identify the behavior to preserve or add.
3. Add or update a focused failing test.
4. Run the focused test and confirm it fails for the expected reason.
5. Implement the smallest change to pass.
6. Re-run the focused test.
7. Run related tests or project-level checks.
8. Refactor only after tests pass.

## If tests are not practical

Explain why, then use another verification method such as a script, typecheck, lint, manual command, or direct inspection.

## Final report

Include test files changed, implementation files changed, and exact verification commands.
